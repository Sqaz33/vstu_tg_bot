# Архитектура Excel-парсера

## Что было исследовано

Для сравнения разметки использовались опубликованные университетом файлы. Они
нужны только для локального исследования и не входят в репозиторий.

| Файл | Формат | Заголовок групп | Особенность |
|---|---|---|---|
| 1 курс ФЭВТ | BIFF `.xls` | строка 9, группы с G, шаг 4 | 9 групп, предметы иногда объединяют две пары и несколько групп |
| 2 курс ФЭВТ | BIFF `.xls` | строка 6, группы с G, шаг 4 | другая стартовая строка при том же смысловом каркасе |
| 1 курс ФАТ | BIFF `.xls` | строка 6 | всего 3 группы, много формально используемых пустых столбцов |
| 1 курс ФТПП | OOXML `.xlsx` | строка 6 | комбинированный заголовок `ЭКОМ-1, ЭКОМ-1в` |

Общая структура: слева месяцы и календарные отметки, затем название дня и номер
учебных часов; правее идут блоки групп. Одна пара обычно занимает три строки, но
предмет, даты, тип, преподаватель и аудитория могут быть объединены по-разному.

## Почему координаты не зашиты

`VstuGridParser` на каждом листе заново определяет:

1. строку с наибольшим количеством названий групп;
2. ширину группового блока по медиане расстояний между заголовками;
3. строки дней по русским названиям дней недели;
4. столбец и начала пар по шаблонам `1-2`, `3-4` и т. д.;
5. области предметов по содержимому и геометрии merged cells;
6. связанные даты, типы занятий, ФИО и аудитории по семантическим классификаторам.

Объединённая область предмета, пересекающая несколько начал пар, превращается в
одно занятие с расширенным интервалом, например `7–10`. Явные даты вида
`14.09, 12.10` хранятся как список дат. Если дат внутри карточки предмета нет,
используется еженедельное правило в границах семестра.

## Слои расширения

### Новый файловый формат

Реализовать `WorkbookReader` в `parsing/readers.py`. Результатом должен быть
`WorkbookGrid`: значения ячеек плюс `CellRegion` для объединённых областей. После
регистрации reader все существующие семантические парсеры смогут его использовать.

### Новая структура факультета

Создать класс-наследник `ScheduleParser`:

- `score(workbook)` — оценка уверенности автоопределения;
- `parse(workbook, faculty)` — формирование `ParsedSchedule`.

Затем зарегистрировать экземпляр в `create_parser_registry()`. Registry выберет
поддерживаемый парсер с максимальной оценкой. Специализированный модуль может
получить более высокий score, не нарушая универсальный fallback.

### Новая веб-страница

Источник отделён от Excel-парсинга. Новый клиент должен обнаружить `SourceFile` и
вернуть `DownloadedFile`; updater, хранилище и Telegram-слой останутся прежними.

## Контроль качества

- synthetic unit-тест проверяет смещённую сетку, объединение двух пар и aliases
  групп;
- один и тот же parser smoke-тестируется на реальном ФЭВТ `.xls`;
- соседние `.xls`/`.xlsx` использовались для проверки автообнаружения;
- замена расписания выполняется одной SQLite-транзакцией;
- исходный `raw_text` сохраняется в БД для диагностики спорных ячеек.

Таблицы университета остаются документами ручной вёрстки. При появлении нового
неоднозначного шаблона предпочтительно добавить специализированный parser с
fixtures, а не усложнять универсальные эвристики до неотлаживаемого состояния.
